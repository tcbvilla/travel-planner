# CSV 数据规范与导入规则

## 来源与编码
- 来源：游戏“导出当前数据”功能。
- 建议编码：UTF-8（若为 GBK 需转码）。

## 必需字段（示例字段名，实际以样例 CSV 校对）
- 成员ID/UID（唯一标识）
- 成员昵称
- 分组/团队
- 战功总量（数值）

## 文件要求
- 两份 CSV：起始快照、结束快照。
- 成员匹配：以 成员ID 为主键对齐；若缺失则以 昵称+分组 兜底并标记“需人工确认”。

## 导入校验
- 字段存在性/类型；
- 重复成员行检测；
- 缺失成员在两次快照差异清单；
- 编码与分隔符自动探测；

## 计算口径
- 战功增量 = 结束快照.战功总量 - 起始快照.战功总量；
- 出勤判定：增量 >= 出勤标准（可配置，默认≥1或按盟规则设定）。
- 分组归属：以起始快照的“分组”为准。

## 实际样例字段（基于两份样例 CSV）
表头（逗号分隔）：
- 成员
- 贡献排行
- 贡献本周
- 战功本周
- 助攻本周
- 捐献本周
- 贡献总量
- 战功总量
- 助攻总量
- 捐献总量
- 势力值
- 所属州
- 分组

建议作为主键匹配字段：
- 首选：成员（昵称，注意同名冲突可能性低但需检测）
- 兜底组合：成员 + 所属州；如仍冲突，再加分组（但分组以起始快照为准，仅用于冲突消解）

分组变更处理：
- 当结束快照中“分组”与起始快照不同，按需求“以考勤起始数据为准”，统计与展示均使用起始快照的分组。

编码与分隔：
- 样例为逗号分隔，字段名为中文；建议统一保存为 UTF-8。

文件命名约定（建议）：
- 起始快照：同盟统计YYYY年MM月DD日HH时mm分ss秒.csv
- 结束快照：同盟统计YYYY年MM月DD日HH时mm分ss秒.csv
- 系统内保存时记录快照拍摄时间（takenAt）以保证可追溯。
