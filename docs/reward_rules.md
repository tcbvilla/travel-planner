# 奖惩与合成规则

## 奖惩类型

### 码表奖惩
- **奖励类型**: 花瓣、花、双花瓣、双花
- **惩罚类型**: 屎粒、屎、双屎粒、双屎
- **码表值**: 所有码表项的 `code_value` 均为 0

### 现金奖惩
- **类型**: 可正可负的现金奖励/惩罚
- **输入**: 用户直接输入数值
- **存储**: 存储在 `cash_amount` 字段中
- **互斥性**: 与码表奖惩类型互斥，不能同时选择

## 合成机制

### 花瓣 → 花 合成
- **触发条件**: 每个团队累计获得 3 个花瓣
- **合成结果**: 自动合成 1 个花
- **处理逻辑**: 
  - 删除 3 个花瓣记录
  - 创建 1 个花记录
  - 记录合成链和日志

### 花 → 现金 合成
- **触发条件**: 每个团队累计获得 3 个花
- **合成结果**: 自动合成 648 元现金奖励
- **处理逻辑**:
  - 删除 3 个花记录
  - 创建 648 元现金记录
  - 记录合成链和日志

### 屎粒 → 屎 合成
- **触发条件**: 每个团队累计获得 3 个屎粒
- **合成结果**: 自动合成 1 个屎
- **处理逻辑**: 同花瓣→花合成

### 屎 → 现金 合成
- **触发条件**: 每个团队累计获得 3 个屎
- **合成结果**: 自动合成 -648 元现金惩罚
- **处理逻辑**: 同花→现金合成，但金额为负数

## 结算逻辑

### 出勤率计算
- **基础出勤率**: 出勤人数 / 总人数
- **团队规模加成**:
  - 40-45人: +3% 出勤率，×1.03 平均战功
  - 46-50人: +5% 出勤率，×1.05 平均战功
- **最终出勤率**: 基础出勤率 + 加成，最高 100%

### 排名计算
- **出勤率排名**: 使用密集排名算法
- **战功增量排名**: 使用密集排名算法
- **失败条件**: 任务失败时使用倒数排名（升序排序）

### 奖惩分配
- **码表奖惩**: 不分割，按排名直接分配
- **现金奖惩**: 可分割，按比例分配给并列团队

## 撤销机制

### 级联撤销
- **触发条件**: 撤销结算时，如果存在合成记录
- **撤销顺序**: 按合成链创建时间倒序撤销
- **恢复逻辑**: 恢复原始记录状态，删除合成记录

### 撤销保护
- **合成后保护**: 如果原始记录已被合成，拒绝撤销
- **批次关联**: 通过 `settlementBatchId` 精确关联撤销目标

## 数据一致性

### 事务处理
- **合成操作**: 使用事务确保原子性
- **撤销操作**: 使用事务确保数据一致性

### 状态管理
- **记录状态**: ACTIVE（活跃）、SYNTHESIZED（已合成）
- **会话状态**: ADDED（已添加）、SAVED（已保存）、SETTLED（已结算）

### 审计日志
- **结算日志**: 记录结算操作和内容
- **合成日志**: 记录合成操作和结果
- **撤销日志**: 记录撤销操作和影响
